# Task Deletion and Archiving System Design

## Overview

This design document outlines the implementation of a task archiving system that allows users to:
1. Archive (soft delete) tasks instead of permanently deleting them
2. View archived tasks in a dedicated view
3. Permanently delete tasks from the archived view
4. Filter between active and archived tasks

### Service Layer Changes

#### TaskService Updates

Modify `TaskService` to support archiving:
```typescript
// src/lib/services/task-service.ts
class TaskService {
  // New method: Archive a task (soft delete)
  archive(taskId: string): Task {
    const existing = this.getById(taskId);
    if (!existing) {
      throw new Error(`Task ${taskId} not found`);
    }
    
    const now = new Date().toISOString();
    return this.update(taskId, {
      archived: true,
      archived_at: now,
    });
  }

  // New method: Restore an archived task
  restore(taskId: string): Task {
    const existing = this.getById(taskId);
    if (!existing) {
      throw new Error(`Task ${taskId} not found`);
    }
    
    return this.update(taskId, {
      archived: false,
      archived_at: undefined,
    });
  }

  // Modify list() to filter out archived tasks by default
  list(filters?: {
    phase?: string;
    priority?: string;
    story_id?: string;
    blocked?: boolean;
    archived?: boolean; // New filter
  }): Task[] {
    // ... existing code
    // Default to showing only non-archived tasks
    const showArchived = filters?.archived ?? false;
    
    // Add archived condition to database query
    if (showArchived) {
      conditions.push(eq(tasks.archived, true));
    } else {
      conditions.push(eq(tasks.archived, false));
    }
    // ... rest of method
  }

  // Update delete() to only work on archived tasks
  delete(taskId: string): void {
    const task = this.getById(taskId);
    if (!task) {
      throw new Error(`Task ${taskId} not found`);
    }
    if (!task.archived) {
      throw new Error(`Task ${taskId} must be archived before deletion`);
    }
    
    // ... existing delete logic
  }
}
```

## UI/UX Considerations

### Visual Design
1. **Archive Filter**: Add a toggle button in the page header next to the story filter
2. **Archived Tasks**: Display with a muted appearance (reduced opacity or different background)
3. **Archive Icon**: Use a box/archive icon for the archive action
4. **Restore Icon**: Use an undo/restore icon for the restore action
5. **Delete Icon**: Use a trash icon with danger styling for permanent deletion

### Interaction Flow
1. **Archive Task**: Single click on archive icon, with instant feedback
2. **View Archived**: Toggle the archive filter to show/hide archived tasks
3. **Restore Task**: Single click on restore icon from archived view
4. **Delete Task**: Click delete icon with confirmation dialog

### Board Behavior
1. **Drag Restrictions**: Archived tasks cannot be dragged to different phases
2. **Phase Display**: Show archived tasks in their last active phase, but visually distinct
3. **Filtering**: Archive filter works alongside story filter

## Migration Strategy

- No data migration needed for existing tasks

## Security Considerations

1. **Permissions**: Ensure only authorized users can archive/restore/delete tasks
2. **Audit Trail**: Log all archive/restore/delete operations in activity log
3. **Soft Delete Safety**: Require tasks to be archived before permanent deletion

## Performance Considerations

1. **Query Optimization**: Add database index on `archived` column
2. **Default Filtering**: Always filter out archived tasks unless explicitly requested
3. **Batch Operations**: Consider batch archive/restore for future enhancement

## Edge Cases

1. **Blocked Tasks**: Archived tasks should not block other tasks
2. **Story References**: Stories should show correct counts excluding archived tasks
3. **Active Sessions**: Prevent archiving tasks with running sessions
4. **Git Branches**: Handle worktrees and branches for archived tasks appropriately

## Future Enhancements

1. **Bulk Operations**: Select multiple tasks for batch archive/restore
2. **Auto-Archive**: Automatically archive tasks in "done" phase after X days
3. **Archive Export**: Export archived tasks for long-term storage
4. **Search**: Include/exclude archived tasks in search results
5. **Restore History**: Track restore operations and show in activity log

## Risks and Mitigations

### Risk 1: Accidental Deletion
**Mitigation**: Require confirmation dialogs, implement restore functionality, log all operations

### Risk 2: Performance Impact
**Mitigation**: Add database indexes, implement efficient filtering, lazy load archived tasks

### Risk 3: UI Complexity
**Mitigation**: Keep UI simple with clear visual indicators, progressive disclosure of features
