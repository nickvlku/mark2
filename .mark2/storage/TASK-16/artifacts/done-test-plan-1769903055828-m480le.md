# Manual Test Plan: Board Pan/Drag and Arrow Key Navigation

## Overview
This test plan covers the new board navigation features:
1. **Drag-to-Pan**: Click and drag on empty space to pan the board horizontally
2. **Arrow Key Navigation**: Left/Right arrow keys scroll the board by one column (~320px)

## Test Environment
- **URL**: http://localhost:3016
- **Port**: 3016
- **Browser**: Any modern browser (Chrome, Firefox, Safari, Edge)

---

## Pre-Test Setup

1. Navigate to http://localhost:3016
2. The board should display with 9 columns (pending → done)
3. Ensure the browser window is narrow enough that not all columns are visible (requires horizontal scrolling)

---

## Test Cases

### TC-1: Drag-to-Pan on Empty Space

**Objective**: Verify that clicking and dragging on empty board space pans the board horizontally.

**Steps**:
1. Navigate to the board
2. Position mouse on empty space between or below task cards (not on a card)
3. Click and hold left mouse button
4. Drag mouse to the left
5. Release mouse button

**Expected Results**:
- [ ] Cursor changes to "grabbing" during drag
- [ ] Board scrolls in the opposite direction of drag (drag left → board scrolls right, revealing columns on the right)
- [ ] Scroll is smooth and responsive
- [ ] Board stops scrolling when mouse is released

---

### TC-2: Drag-to-Pan Does NOT Interfere with Card Drag

**Objective**: Verify that dragging on task cards still works for card drag-and-drop (not panning).

**Steps**:
1. Navigate to the board
2. Click and drag on a task card
3. Drag it to a different column
4. Release

**Expected Results**:
- [ ] Card follows the mouse (not board panning)
- [ ] Card can be dropped in another column
- [ ] Phase change is saved successfully
- [ ] Board does NOT pan during card drag

---

### TC-3: Arrow Key Navigation - Right

**Objective**: Verify that pressing Right arrow key scrolls the board to the right.

**Steps**:
1. Navigate to the board
2. Click somewhere on the page (not in an input field)
3. Press the Right arrow key
4. Press it again

**Expected Results**:
- [ ] Board smoothly scrolls right by approximately one column width (~320px)
- [ ] Each press scrolls an additional column
- [ ] Scrolling is smooth (animated)

---

### TC-4: Arrow Key Navigation - Left

**Objective**: Verify that pressing Left arrow key scrolls the board to the left.

**Steps**:
1. Navigate to the board
2. First scroll to the right (so there's content to the left)
3. Press the Left arrow key
4. Press it again

**Expected Results**:
- [ ] Board smoothly scrolls left by approximately one column width (~320px)
- [ ] Each press scrolls an additional column
- [ ] Scrolling is smooth (animated)

---

### TC-5: Arrow Keys Should NOT Work When Input is Focused

**Objective**: Verify that arrow keys don't scroll the board when typing in an input field.

**Steps**:
1. Navigate to the board
2. Click "+ Task" to open the create task dialog
3. Focus on the title input field
4. Press Left/Right arrow keys

**Expected Results**:
- [ ] Arrow keys move cursor in the input field (normal text navigation)
- [ ] Board does NOT scroll
- [ ] After closing the dialog, arrow keys should work for board navigation again

---

### TC-6: Arrow Keys Should NOT Work When Dialog is Open

**Objective**: Verify that arrow keys don't scroll when a dialog is open.

**Steps**:
1. Navigate to the board
2. Click on a task card to open the task detail slide-over
3. Press Left/Right arrow keys

**Expected Results**:
- [ ] Board does NOT scroll while dialog/slide-over is open
- [ ] After closing the dialog, arrow keys work normally

---

### TC-7: Pan Gesture Threshold

**Objective**: Verify that small movements (clicks) don't trigger panning.

**Steps**:
1. Navigate to the board
2. Click on empty space (don't drag)
3. Click and move mouse less than 5 pixels, then release

**Expected Results**:
- [ ] Simple clicks do not cause any panning
- [ ] Very small movements (< 5px) do not trigger pan mode
- [ ] Only movements > 5px activate panning

---

### TC-8: Cursor Visual Feedback

**Objective**: Verify proper cursor states for visual feedback.

**Steps**:
1. Navigate to the board
2. Hover over empty space (between cards)
3. Click and drag on empty space
4. Hover over a task card

**Expected Results**:
- [ ] Default cursor on board empty space is "grab" (open hand)
- [ ] Cursor changes to "grabbing" (closed hand) while dragging
- [ ] Cursor on task cards is default pointer (for clickability)

---

### TC-9: Native Scrollbar Still Works

**Objective**: Verify that the native scrollbar still functions.

**Steps**:
1. Navigate to the board
2. Use the horizontal scrollbar at the bottom to scroll

**Expected Results**:
- [ ] Native scrollbar scrolling works as expected
- [ ] Can drag the scrollbar thumb to scroll
- [ ] Can click on scrollbar track to jump

---

### TC-10: Touch Device Compatibility (if applicable)

**Objective**: Verify pan works on touch devices.

**Steps** (on touch device or using browser devtools touch simulation):
1. Navigate to the board
2. Touch and drag on empty space
3. Touch and drag on a task card

**Expected Results**:
- [ ] Dragging on empty space pans the board
- [ ] Dragging on a card initiates card drag-and-drop (not pan)
- [ ] Two-finger scroll (native) also works

## Edge Cases

### EC-1: Rapid Arrow Key Presses
- Press arrow keys rapidly multiple times
- Expected: Board should handle rapid presses smoothly without stuttering

### EC-2: Pan While at Boundary
- Scroll to the rightmost position
- Try to drag/pan further right
- Expected: Board should stop at the boundary gracefully

### EC-3: Keyboard Navigation with Modifier Keys
- Press Ctrl+ArrowRight or Shift+ArrowLeft
- Expected: Should still scroll (no special modifier behavior)
